## Categories

- **Local File Inclusion (LFI):** Understanding file-inclusion weaknesses and their security impact.
- **PHP Source Disclosure:** Investigating situations where application source code or implementation details become exposed.
- **PHP Wrappers:** Studying wrapper-related web application security concepts.
- **WordPress Security:** Enumeration and configuration-file security.
- **Credential Discovery:** Investigating exposed authentication information in controlled environments.
- **Encoding & Analysis:** Using Base64 decoding and CyberChef-style analysis to understand encoded data.
- **Hidden Files & Backdoors:** Investigating suspicious files and LFI-related backdoor scenarios.
- **Web Application Reconnaissance:** Connecting enumeration, source analysis, configuration review, and vulnerability research.

## Learning Path

A practical progression through these cybersecurity labs is:

1. Start with **web reconnaissance and WordPress enumeration**.
2. Study **WordPress configuration and credential exposure**.
3. Learn the fundamentals of **LFI and source-code investigation**.
4. Explore **PHP source disclosure and wrapper concepts**.
5. Practice **encoded-data analysis and Base64 decoding**.
6. Investigate hidden files and application artifacts.
7. Finish with the **LFI backdoor** challenges to understand how multiple web-security weaknesses can connect in a controlled environment.

## How to Use the Labs

Use these exercises only in authorized lab environments.

Recommended workflow:

1. Read the lab objective before beginning.
2. Identify the application, endpoint, configuration, or artifact being investigated.
3. Perform controlled reconnaissance against the provided lab target.
4. Document discovered paths, application behavior, source-code clues, and configuration findings.
5. Investigate the vulnerability only within the authorized environment.
6. Record the security impact and potential remediation.
7. Consider defensive measures such as input validation, safe file handling, least privilege, secure WordPress configuration, and removal of unnecessary source-code exposure.

For LFI and backdoor-focused exercises, use isolated training environments and never test against systems without explicit authorization.
